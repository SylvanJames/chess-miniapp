# 国际象棋 · 双人对战 + 语音聊天

小程序风格（手机端布局）的国际象棋对战程序。两人通过房间号配对，对局中可**实时语音对讲**，也可文字聊天。

## 快速启动

```bash
cd chess-miniapp
node server.js          # 默认端口 8848
```

打开 `http://localhost:8848`，在手机上访问时用同一局域网 IP，例如 `http://192.168.1.10:8848`。

> **语音功能需要 HTTPS**：浏览器仅在 `https://` 或 `localhost` 下允许调用麦克风。
> 局域网内手机测试语音时，需用 HTTPS 或借助 `ngrok` / `cloudflared` 等内网穿透工具。

## 玩法

1. **一方创建房间** → 得到 4 位房间号（如 `H635`）
2. **另一方输入房间号加入** → 白方先行
3. 点击语音条上的 **🎙️** 发起语音 → 对方接听后即开始通话
4. 对局中随时可点击 **💬** 发送文字消息

## 功能清单

| 模块 | 能力 |
|---|---|
| **对局** | 完整国际象棋规则：王车易位、吃过路兵、兵升变、将死/逼和/50 回合/子力不足和棋 |
| **助战** | 合法走法高亮（空心圈=可走空位，粗环=可吃子）、上一步标记、将军红闪、走子记谱 SAN |
| **语音** | WebRTC 点对点实时对讲、来电弹窗、静音、挂断、通话计时、延迟显示、说话波形动画 |
| **文字** | 气泡式聊天、预设快捷短语、未读角标、系统消息（加入/离开/悔棋/和棋） |
| **协商** | 悔棋、提和需双方同意；认输需二次确认 |
| **体验** | 黑方自动翻转视角、走子音效、手机安全区适配（刘海屏） |

## 语音实现说明

采用 **WebRTC** 而非服务器转发：

```
主叫 A                 信令服务器              被叫 B
  │  ── invite ──────────→│──────── invite ──→  │
  │  ←──────────────── accept ───────────────  │
  │  ── offer(SDP) ──────→│────── offer ────→   │
  │  ←──────────────── answer(SDP) ──────────   │
  │  ⇄ ICE 候选交换（双向中转）                  │
  │                                             │
  └══════ 音频流 点对点直连（不经服务器）═══════┘
```

- **音频不经过服务器**：两人直接 P2P 传输，延迟低、隐私好、服务器零带宽成本
- **服务器只转发信令**：`invite / accept / decline / offer / answer / ice / mute / hangup`
- **内置三组 STUN**：Google / Cloudflare，用于穿透 NAT 发现公网地址
- **音频优化**：回声消除（防啸叫）、降噪、自动增益，单声道
- **ICE 候选缓冲**：远端描述未就绪时先缓存候选，就绪后批量注入，避免丢包导致连接失败

> 生产环境建议补充 **TURN 服务器**（如 coturn），以应对对称型 NAT / 严格企业防火墙场景。

## 文件结构

```
chess-miniapp/
├── server.js              # HTTP 静态服务 + WebSocket 房间/走子/聊天/语音信令（零依赖）
├── public/
│   ├── index.html         # 小程序风格页面骨架
│   ├── style.css          # 手机端样式（含语音条、来电弹窗、波形动画）
│   ├── chess.js           # 国际象棋规则引擎（含 FEN/SAN/合法性校验）
│   ├── voice.js           # WebRTC 语音模块（采集/信令/连接管理/音量检测）
│   └── app.js             # 页面主逻辑（棋盘渲染、交互、聊天、语音 UI 状态机）
├── test.js                # 规则单测
├── e2e.js                 # 对战联调
└── voice-test.js          # 语音信令测试
```

**零第三方依赖**：WebSocket 服务端自实现（RFC6455 握手 + 掩码帧 + 分片解码），前端不引入任何框架或库。
